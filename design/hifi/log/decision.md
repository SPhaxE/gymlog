## 钢板打孔日历（用户 2026-10-06 的决定，最终规格在 `plate-plan.md`）
- 用 C 的点阵，做成钢板打孔：板后透出荧光绿，练过的日子是孔，没练的只有淡标记；光影随页面滑动变化；代码简单、省内存。
- 走过的弯路：先做了「精加工孔」（倒角环、发光边）→ 被否（「不是这种精致孔」，要冲压板材冲出来的空洞，甚至像弹孔）→ 又试了四种冲孔（净冲孔 / 毛刺孔 / 弹孔式 / 偏心卷边孔）→ 用户看真机大小渲染后觉得混在一起效果一般，**只留第一种「净冲孔」**。光影参考用户三联图的**右边那张**（一大团软光偏在右中部、板右外缘漏光）。
- 实现：一张静态 SVG + 板后几层灯箱，全是合成线程的 CSS 滚动驱动动画（静止 = 亮区在右，滑到行程 = 亮区到左，两侧漏光换边，钢面一道淡反光）；`prefers-reduced-motion` 与不支持的浏览器静止。

## 页面代码的判断（不来自 Stitch）
- **一次渲染 8 周**，底部「更早的训练 · 还有 N 周」再展开 8 周（ia：数百条分段加载；不做无限滚动，避免找不到底）。

## 训练详情 P08（取 Stitch l6 D，页面代码另做判断）
- 取：汇总三格（动作 / 组数 / 总负荷）、「新纪录」一行（骨白标 + 动作 + 预估 1RM + 涨幅）、每个动作一张卡（卡头 = 名称 + PR 标 + 箭头，点进曲线页）、热身组灰字 + 虚线「热身」标。
- 舍：D 页头里的英文小字、统计卡里的同心环装饰（这一页不要荧光和装饰，留给记录页的钢板）。
- 判断：**每一组的重量和次数各自右对齐成定宽列**，RPE 单独一列——一列看下去，数不会因为有没有 RPE、几位数而左右错开；递减组标「递减」；单侧动作写「左 8 · 右 7」；没做的动作写「未做」；新纪录的增幅和结算页是同一个 `summarize`（比「之前最好」多了多少）。
- 钻入转场：记录页那一行的日期 → 详情标题、部位 → 副标题（M09，`drillName('name' | 'num')`）；从动作曲线页返回时，目标页可能是增量页也可能是这里，所以曲线页的返回等「不是曲线页的那个 `data-drill-ready`」挂好。
- 删除训练放在右上角的溢出菜单。

## 删除训练（取 Stitch l6 E + ia §1.8 / §5）
- 流程：详情右上角 ⋮ → 底部面板（拇指区，里面一个危险操作「删除这次训练」）→ 二次确认对话框（日期 · 部位 · 组数一行 +「删除后，近 7 天容量、恢复度、趋势和新纪录都会重新计算，不能撤销」；取消 / 删除，删除是危险色）→ 回记录页 + 轻提示「已删除 10月3日 周六 的训练」。
- **二次确认、不可撤销**（和 Stitch E、ia 一致）。之前 playground 里那个带「撤销」的删除演示改成同一套；「可撤销」只剩 Toast 组件自己的能力演示。
- 为什么不是「先删再给撤销」：训练记录是用户自己一组一组打的卡，误删代价高于多点一下；对话框里写明后果，比事后撤销更诚实。
- **先回记录页、再删**（同一次点击里批量更新）：否则详情页会闪出一下「这次训练已经不在了」。
- **没有要手动失效的缓存**：容量 / 恢复度 / 趋势 / PR / 处方 / 增量 / 记录页的周合计和钢板孔数，全是各页从 `history` 现算的（`useMemo` 依赖它），`deleteSession` 只是 `history.filter`，其余自动重算；减量状态原样保留；进行中的训练和草稿不受影响。
- 演示场景（`?scenario=`）不读写存储：删掉的训练记在 `useSource` 模块级的内存里（刷新复位），所有用它的页面订阅同一份，删完去别的页也已重算——保证场景里点删除不是死按钮。身体页直接读场景，不受影响（只影响 `?scenario=` 的截图 / 回归，真用户走存储）。
- 牛龄页注明「删除可能降级」（ia §1.8 末）留给 6d：牛龄页还没做。
