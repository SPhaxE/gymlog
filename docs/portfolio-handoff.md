## 1. 一页结论

- **项目**：慢牛 Milo——给刚过新手期的健身者的 Android 训练 App：根据恢复、训练量和近期表现，告诉你今天练什么、每组加多少（渐进超负荷 × 超量恢复）。Slogan「慢慢变牛。」
- **状态**：App、规范、组件库、方案台、演示页全部定稿上线；安卓 debug APK 已用新图标打好。
  - 线上演示：<https://gymlog-taupe.vercel.app/demo>（电脑打开左讲解右手机，手机打开直接进 App）
  - APK：仓库 `main` 的 `apk/milo-debug.apk`（CI 每次推 `main` 自动打包；本次源提交 `d419d8e`）
- **主线**：一个人 + AI，按「交互五层 → 低保真 → Stitch 视觉参考 → 高保真代码 → 用户逐项审查」把一个训练 App 从定义做到能装在手机上；**Token 体系 + 门禁脚本**保证几百次迭代不走样；浅色模式是对 Token 体系的验收（组件基本不改，换一套语义色映射就整体换肤）。

### 5.2 两段好讲的「反转」

- **浅色：深色岛被否掉**。第一版浅色想保住材质和舞台感，留了 5 块局部深色；用户一句「要真·全局浅色」否掉，于是每个光效都重想浅色下怎么成立（原则「提亮 → 压暗」）。人体经历 L1–L4 → L2 的四个变体 L2a–d × 6 种描边 → 先选 L2d 磨砂 → **最后定 L2a 轻盈**。
- **深浅转场：三轮**。第一版纯色液体（W1–W4）→ 用户「效果一般，没有渐变」并给了 AE 熔流拆解 → 第二版拆成走向 × 渐变两轴、WebGL 逐像素 → 用户「白色区域要能透出后面的页面，动画是给渲染更多时间，不是完全挡住」→ 改成旧页面快照随色带擦掉 → 用户「/preview 很卡」→ 性能优化（每帧整页样式重算 240 ms → 只算一个伪元素；着色器两遍）→ 选定 R1 × G1，从点的按钮晕开。

## 6. 浅色 / Token 验收要点（讲「一键换肤」那段用）

- 页面只用语义色 `--milo-color-*`；`tokens.css` 里 `:root` 是深色、`[data-theme='light']` 是浅色；切主题 = 改 `<html data-theme>`。代码级一键：`src/styles/theme.ts` 的 `DEFAULT_THEME`。
- 组件零改动就能切的：绝大多数页面。改了的只有三类，正好说明 Token 哪里不够：
  1. **荧光当字 / 线**：浅色里荧光当线看不见 → 新增 `accent/ink`，32 处换过去；
  2. **直接写了原色的组件**（Logo、道具图标、小牛、选肌肉的人体）→ 新增 `brand/*`、`picker/*`；
  3. **画布特效**在 JS 里取色 → 改成从元素自己身上读 `fx/*` 语义色，切主题时重画。
- 最终浅色规则：不写描边、层次用 `--depth-*`；主视觉只有白 / 荧光 / 黑；深色是荧光的焦点浅色仍是荧光（`--fluo-*`）；浅色墨黑只对位深色的骨白实心；门禁逐页比对深浅两套的荧光焦点。
- 质量：两套主题都跑对比度；深色在做浅色期间逐像素未变。
