# UIUX-AI 协作工作流

> 适用：一人 + AI 协作，把移动优先的 App / Web 从 0 做到可交付（或把原型规范化）。只以产出与门禁验收，不规定哪一步由人或 AI 做。
> 读法：§0 原则必读；按 §2 阶段推进；做每页用 §3；拍板与汇报按 §4；门禁 §6；换窗口 §8；踩坑查 §10；模板在附录。

---

## 0. 原则

1. **规范先行**：规范第一版（Token + 规则 + 核心组件）定稿前不做业务页；之后规范只经 §2.4 的变更流程增补，页面里不临时发明样式。
2. **单一源头**：设计 Token 只在仓库的一个数据文件里定义，CSS 变量、代码常量、设计工具里的变量都由脚本生成，不手改生成物。
3. **只依赖文件**：每页的输入只来自文件（规范、Token、组件、`ia.md`、选定线框、数据、决定记录），不依赖对话——对话会被压缩，窗口和 AI 都会换。
4. **能自动查的不靠人记**：每条规则尽量落成一条门禁断言；不过关不进下一步。
5. **用户拍板才定稿**：视觉 / 交互选择由用户定或明确授权；视效类选择用实时渲染并排比较，不用静态图；落选方案保留。
6. **决定连原话一起记**：每个决定记日期、用户原话、谁定的；后来者按原话判断。
7. **同源归组改**：一条反馈先找同原因的其他位置，改规范，全局一次改完。
8. **目标定范围**：先明确为谁做（上线 / 展示 / 比赛），用不上的直接砍；做的部分把状态、空态、动效做全。优先复用现成的，少写新代码。
9. **定稿有作用域保护**：已定稿的页面或主题，后续改动只写在新作用域里，并用逐像素回归证明旧的没变。
10. **结论先行、只报结果**：对用户先说结论，只说改了什么、能不能看；不报过程（命令、CI、分支），除非需要用户处理。

## 1. 最常见的代价（速览）

| 问题 | 做法 | 见 |
|---|---|---|
| 对话被自动压缩，约定丢失 | 每次推送同步更新交接文件；逼近上限才换窗口 | §8 |
| 页面「没设计感」被退回 | 回到五层模型从结构层改，不在表现层堆装饰 | §3 |
| 结构问题只在真机暴露 | 能装机就尽早真机走主流程 | 阶段 7 |
| 同一状态在屏上出现两次 | 同一个东西只出现一次，跨页用同一元素过渡 | §5 |
| 第二套主题做成了反色、焦点丢失 | 按角色对等映射，脚本逐元素比对两套主题 | 阶段 8 |
| 静态图比不出视效差异 | 方案台实时渲染并排 | §4.4 |
| 以为已上线（或误判没上线） | 构建时写入提交号，在线上包里核对 | §7 |
| 密钥反复丢失 | 约定位置 + 交接写明 + 平台环境密钥 | §7 |
| 门禁反复整套重跑拖慢开发 | 快检每次跑；长门禁阶段末后台跑、只重跑失败项 | §6 |

## 2. 阶段

```
1 产品定义 → 2 信息架构 → 3 视觉方向 → 4 规范与 Token → 5 组件与壳 → 6 逐页 → 7 真机走查 → 8 主题扩展（可选）→ 9 展示（可选）
（6、7 中缺规范 → 回 4；品牌 / 增长层若有，放在 5 与 6 之间，因为它会改范围和口径）
```

| 阶段 | 产出 | 过关 |
|---|---|---|
| 1 产品定义 | `brief.md`（含决定记录） | 目标可衡量；P0 都在核心闭环上；术语与数字只有一个版本；非目标写明；写清为谁做 |
| 2 信息架构 | `ia.md`、mock 数据、灰阶线框、低保真原型 | 每个用户任务有 P0 功能与流程；P0 有规格含边界；流程无断头；每页标出第一优先信息 / 主操作 / 导航，命中区 ≥ 48 |
| 3 视觉方向 | 参考与视觉语言、方向稿 | 一句话说清与竞品的视觉差异；选择理由已记录 |
| 4 规范与 Token | Token 数据文件及生成物、`DESIGN.md`、规范页 | 标杆页只用 Token；对比度表全过；`DESIGN.md` 写全（附录 C） |
| 5 组件与壳 | 组件库、组件预览页、App 壳、演示入口 | 全部组件 × 全部交互态可预览，覆盖测试过；无写死值 |
| 6 逐页 | 页面、方案台条目、门禁断言 | 每页按 §3；`check` + 门禁全绿；可在线查看 |
| 7 真机走查 | 走查文档、分阶段汇报 | 每条批注有根因与归组；新规则进 `DESIGN.md` 和门禁 |
| 8 主题扩展 | 第二套语义色映射 | 组件不改即可换肤；旧主题逐像素不变；焦点角色对等 |
| 9 展示 | 案例页、样机图、录屏 | 真实样机（附录 G）；展示选择过程 |

### 2.1 产品定义
写：一句话定位；名称 / slogan（候选逐个写理由，无记忆点的淘汰）；目标用户（人群 → 场景 → 痛点）；产品目标各 2–3 条并配指标；核心体验闭环；P0 / P1 与非目标；竞品 ≤ 3；统一口径表（术语、数值、单位、权益）；品牌关键词 3–5 个；为谁做。模板见附录 A。

### 2.2 信息架构（五层模型自下而上：战略 → 范围 → 结构 → 框架）
1. 战略 → 用户任务：把痛点改写成任务，每个任务对应至少一个 P0。
2. 范围：每个 P0 写描述、输入、输出、规则、边界（空 / 上限 / 失败 / 中断）；列内容需求并准备真实文案与 mock 数据，不用占位文字。
3. 结构：站点地图、页面清单（名称取自口径表）、3–5 条核心流程（用户动作 → 系统反馈，含分支、异常、返回、中途退出）、路由表（入口、返回、刷新保留、数据态）。
4. 框架：每页 2–3 个灰阶方案，用可运行的线框（真实数据 + 真实素材，便于截图和自动检查），每个方案叠**手指热区**（拇指可达区底图 + 每个命中框尺寸），标出第一优先信息、主操作、导航。全局导航若承载状态（进度、计时等），单独写一份对应关系说明再动手。
5. 低保真原型点通全部核心流程；原型只作行为参照，正式实现不复用其业务代码。模板见附录 B。

### 2.3 视觉方向
同品类参考 3 个 + 跨品类 2–3 个，标注各借鉴什么；参考图多时逐张分析，提炼成「视觉语言」（配色角色、材质、版式、数字字体、动效气质）。在同一个标杆页上出 2–3 个方向（AI 出图工具每个方向单开一个项目，否则会趋同），用户选或混搭（写明吸收了什么）。方向稿是参考，不是规范。

### 2.4 规范与 Token
- Token 数据文件定义：原色、**按角色命名**的语义色（每套主题一个映射）、数值（间距、尺寸、圆角、时长、曲线、比例、透明度）、文字样式、对比度校验对。
- 生成脚本输出：CSS 变量（按主题分组）、代码常量（画布 / 动画用）、设计工具导入数据、对比度表（不达标构建失败）。
- `DESIGN.md` 只写 Token 表达不了的规则（附录 C），每条带日期与来由。
- **变更流程**：改 Token 或规则 → 重新生成 → 在规范页 / 组件预览页核对 → 决定记录记一条（改了什么、影响哪些页）。

### 2.5 组件与壳
- 组件预览页覆盖全部组件 × 全部交互态与动效；用测试保证组件库每个导出都在预览页里。
- 内部页各司其职、不重复：组件预览（只放组件）、规范页（只放规则与 Token）、方案台（只放待选与落选方案）、演示页（电脑上讲解 + 手机框里跑产品）。
- 壳先做好：主题切换、安全区与沉浸式全屏、转场框架、返回键。
- 组件或规范更新时，组件预览页和演示页同步更新。

### 2.6–2.7 逐页、真机走查
见 §3、§3.3。

### 2.8 主题扩展（第二套主题 = Token 体系的验收）
1. 只换语义色映射，组件不改；不保留旧主题的局部区块，特效可简化或省略。
2. 先量化再改：焦点色在新底上是否仍是最亮 / 最显眼的元素（明度、偏色量），用数据定改法。
3. 底色用中性色；大面积氛围层会给底色染色，用不上就去掉。
4. 立体手段按主题选：深底用发丝描边，浅底用拟真阴影（接触影 + 环境影，凹陷用内阴影）；只保留功能性描边（选中环、聚焦环、复选框）。
5. **按角色对等，不按明暗反转**：旧主题里是焦点色的，新主题里仍是焦点色，看不清就补可读性（字：保持深色、下方加焦点色底条；小块：焦点色底 + 深色字 + 下沿暗边；线 / 点：焦点色 + 细深色描影）。只有中性强调色（如深色主题里的浅色实心）才对位成新主题的深色实心。
6. 主视觉色数收敛，去掉中间色。
7. 每页两套主题并排重判层级：同比例的灰在浅底上会变重，选中态可能比未选还暗。
8. 用户看不到的主题分支直接砍（例如首次引导只在默认主题出现）。
9. 门禁：旧主题逐像素回归；跨主题逐元素比对焦点角色（§6.3）。
10. 内部工具页最前面放全局主题开关。

### 2.9 展示
各阶段顺手存素材（任务表、线框、方向对比、规范页、组件矩阵、方案台选择过程、走查前后对照、录屏）。界面用真实样机（附录 G），动效用录屏。

## 3. 逐页流程

### 3.1 五步

| 步 | 做什么 | 过关 |
|---|---|---|
| ① 结构与线框 | 写五层分析（定稿后放页面文件头注释，附录 E）；出 2–3 个带手指热区的灰阶方案 | 命中框 ≥ 48；主操作在拇指易达区；无死路；**用户选定** |
| ② 视觉参考（仅当本页引入新的视觉形态） | 用选定线框 + `DESIGN.md` 让出图工具出多个强度 / 变体 | **用户选或混搭**，取舍理由记入决定记录 |
| ③ 实现 | 缺组件先进组件预览页；缺规范先走变更流程；有多种视效可能的放方案台 | `check` 全绿；无写死值；交互硬规则过 |
| ④ 审查 | 截图 + 录屏推到用户窗口，方案台给可复现组合的链接 | **用户点头**；每轮改动重截 |
| ⑤ 定稿 | 选定的设为默认（落选留方案台）；同步演示页、组件预览页、`DESIGN.md`、`ia.md`、决定记录；为新规则加门禁断言；发布并核对线上 | 门禁全绿；线上为新版本 |

只复用现有组件、无新视觉形态的页面：①（可只出一个方案）→ ③ → ④ → ⑤。

**授权时的判据**（用户说「按你的判断」时）：第一优先信息最先被读到；一屏一个焦点；主操作在拇指区；不给死路；不编造内容；去掉装饰性外文与重复的关闭入口。判据和结论写进决定记录。

**上下文包**（每页的全部输入）：`DESIGN.md`、Token 生成物、组件库、`ia.md` 本页条目、选定线框、数据、视觉参考、页面头注释与决定记录。

**演示数据要设计**：首屏都有内容、每种状态都能出现；生成规则写清并有测试；测试不依赖当天日期和时区。

### 3.2 流程级自查（一条流程的页面做完后）
从头到尾走通；返回行为与 `ia.md` 一致；跨页数据正确、刷新按约定保留；按 Nielsen 10 条启发式检查并记录修复。

### 3.3 真机走查（阶段 7，用户在真机上批注）
1. 逐项对照：现象 → 根因 → 改法；原始批注存档。
2. 同源归组，每组一个统一改法。
3. 新规则单列，每条对应一条门禁断言。
4. 列出「先按默认做、不同意再改」的低风险条目，不逐条等拍板。
5. 按依赖分阶段；阶段末才跑长门禁；每阶段汇报一次（走查时 | 现在 | 说明）。
6. 进度、每轮选择、每阶段落地记录都在同一份走查文档（附录 J）。

## 4. 协作协议

### 4.1 拍板
- 需用户定：线框、视觉参考、审查是否通过、范围变化、不可逆操作、与既有规则冲突的改动。
- 给选项要带推荐（放第一、说理由），不列不推荐的。
- 授权分三级，记入决定记录的「来源」：用户 / 用户授权 AI 定 / AI 判断（用户可推翻）。被授权仍须分析，并给出判据和对照图。
- 新窗口先问交接里的待定问题，再动手。
- 用户的节奏指令（「不急」「做完再跑」）照原话执行。

### 4.2 推材料
- 要用户看的图直接发到用户窗口，不只给路径。
- 动效用视频（MP4），不用 GIF；超长图存为单页 PDF。
- 汇报用一张左图右文的长图（前 | 后 | 说明）。

### 4.3 入口文件
根目录放 AI 客户端入口（如 `CLAUDE.md` / `AGENTS.md`）：先读什么、不许破的规则（每条带日期）、动手前后的命令。用户立长期规矩时当场写入。第三方技能只当参考，与项目规则冲突时以项目为准，并在入口文件写明。

### 4.4 方案台
- 视效、材质、配色、组件形态有两种以上可能时使用。
- 一个内部页按组排列，组内用真实组件和真实数据实时渲染；可跨组自由组合，组合写进地址参数。
- 选定后设为默认并标注；落选与旧默认不删。不放截图。

## 5. 交互与视觉硬规则（可直接复用）

1. 命中区 ≥ 48 × 48（视觉可小，用伪元素或内边距补）；相邻命中区不重叠。
2. 一屏一个主操作，放在拇指区；同一件事不在两处各放一个按钮。
3. 不给死路：主按钮不做禁用态，缺什么就把按钮变成「去补什么」。
4. 提示 / 报错行始终占位，出现时不挤动控件。
5. 滚动容器里的网格设 `grid-auto-rows: max-content`。
6. 自带键盘按需出现。
7. 临时面板点别处即收起。
8. 转场进行中的点击不能丢（见 §10）。
9. 底部固定按钮 / 导航下垫渐隐层。
10. 同一个东西屏上只出现一次；跨页时用同一元素过渡。
11. 同一个数只有一个口径。
12. 对比度：正文 ≥ 4.5，大字 ≥ 3；按实际底色（含半透明叠加）计算。
13. 页面标题位置稳定；页头随内容滚走；长页提供回到顶部。
14. 可撤销的操作用底部面板，不可撤销的用居中对话框。
15. 内容不足一屏不滚动；定高面板按内容高度打开，面板内不出滚动。
16. 一行只放一件事，长名称独占一行；多行标题 `text-wrap: balance`，正文 `pretty`；两列读数基线对齐。
17. 产品界面不出现开发 / 演示说明文字。
18. 状态以真值为准，同一判断处处一致。
19. 每个出现都有退场；退场比进场快、用加速曲线。

**焦点色**分两级：焦点面（主按钮、关键成就卡）每屏一处；焦点点缀（小标、曲线末点、上涨箭头）可多处。中性实心色只给选中和主数字；重复出现的标记用线 / 点，不用实心块。

**动效**：维护一份动效清单作为验收参照，每个落点写进 `DESIGN.md`（用在哪、为什么）；转场表写明各类转场的时长与曲线。描线动画「从下到上」优先于「从左到右」。

**性能与降级**（视效不降）：
- 静态层只在变化时画，每帧只画会动的部分。
- 画布滤镜（如模糊）对每一笔都生效：加法叠加的内容先全部画好，再整体模糊一次。
- 外层有 CSS 模糊的画布用 1 倍分辨率绘制；持续光效只动 `transform` / `opacity`。
- 画布动画离开视口或页面隐藏时停止，约 30 帧即可；尺寸监听回报相同尺寸时不重画。
- 跳过量化后全透明的绘制。
- 减少动态效果设置下定格或只淡入。重页面借转场时间加载。

## 6. 门禁

### 6.1 三层
| 层 | 内容 | 何时跑 |
|---|---|---|
| 快检 `check` | 类型检查、单测、写死值扫描（颜色字面量 / 颜色函数 / px / ms；断点须等于 Token）、Token 生成（含对比度）、构建 | 每次改动前后、推送前 |
| 全流程 `gate` | 无头浏览器走主流程 × 两种屏宽：地址、横向溢出、被压扁的块、命中区、对比度、页面报错、禁用词、各页断言、主题检查、演示页 | 阶段收尾、发布前；后台跑 |
| 回归 | 已定稿主题逐像素比对（冻结动画、隐藏画布、固定随机种子与时钟）；画布另截图人工看 | 动到共享样式或 Token 时 |

### 6.2 用法
- 长门禁后台跑，所有改动做完再跑，不在中途反复跑。
- 按「类别 × 屏宽」并行；单步超时即报错并给出所在行；失败只重跑失败项；日常只跑改到的测试或某一类。
- 用构建产物 + 预览服务器跑，比开发服务器快。
- 失败时打印交互时间线（点击、面板出现 / 消失、转场状态）。
- 用户每立一条规则，加一条断言。

### 6.3 写门禁的注意
- DOM 检查看不到遮挡，关键视觉配合截图。
- 跨主题比对时：跳过正在运行动画的元素；字色只比有自身文字的元素；边框色只比确有边框的元素（否则会读到 `currentColor`）；判断「是否仍为焦点色」时往上查几层祖先（焦点色底上的深色字算合格）。
- 偶发超时先单独重跑，排除 CPU 争用，不靠放宽阈值掩盖。
- 重页面切主题需要更长的等待。
- 阴影层数按顶层逗号数，不按颜色函数个数。

## 7. 工程与发布

- 发布方式按用户选择；若是「本机门禁过即推主干」，CI 后台跑，红了立即补修复，只在原因不在本次改动时停下来问。
- 工作分支与主干同步推送；预览部署只构建主干，节省部署配额。
- **核对上线**：构建时写入提交号（产品里也可显示），在线上入口脚本里搜本次提交号；不要拿本地构建的文件名哈希比线上（必然不同）。部署通常需要几分钟。
- CI 自动提交回主干的产物会触发「忽略构建」规则：推前先快进到最新主干；产物最好放到单独分支或 Release。
- 分清哪些目录会被拷进公开站点；密钥绝不放进这些目录。
- 托管平台的访问保护会挡住云端会话的线上检查。
- 密钥不进提交（推送保护会整体拒绝）；放在被忽略的约定位置或平台环境密钥中；不在输出、日志、截图、提交信息里打印；交接写明位置。
- 不关闭 TLS 校验；沙盒浏览器不信任代理证书时，外部资源由脚本代取。

## 8. 会话与上下文

1. 每次推送时，同一提交里更新交接文件（附录 I）。
2. 只在上下文逼近上限时停下：写好交接、推送、告诉用户换窗口并给出可直接粘贴的开工指令；完成一个阶段不必换窗口。
3. 发现对话已被压缩：先写交接再换窗口，不继续干。
4. 交接放在新窗口一定能看到的分支（通常是主干）。环境一节写明密钥位置和新容器需要补装的东西。
5. 新窗口：读交接 → 读入口文件 → 先问待定问题 → 动手。
6. 截图先拼成对照图再看；大文件按需读片段。
7. 临近用量限额先写交接。临时容器里未推送的内容、写入的密钥文件都会丢失。

## 9. 素材

| 素材 | 规则 |
|---|---|
| 专业图（解剖、器械等） | 只用真实授权素材；AI 生成的只作参考 |
| 角色 / 吉祥物 / 场景 | 按意向图用出图工具重制；纯色底（品红）出图后抠图；光效由代码生成，源图不带光 |
| 商品 | 只用实物图 |
| 品牌与商家 | 演示用的一律虚构，不仿冒真实品牌 |

抠图：从纯色底边缘反解透明度；实心区内收防止色边；「挖空被包围的底色」不能用于与底色同暗的部位；成品尺寸上轻微羽化。源图带泛光时重出无光源图，不在抠图代码里硬补。提示词与状态矩阵存进仓库。

## 10. 坑表

| 症状 | 原因 | 处理 |
|---|---|---|
| 滚动区里的行被压扁、内容重叠 | 滚动容器内的网格行高被压到最小 | `grid-auto-rows: max-content`；门禁查「被压扁的块」 |
| 转场中点击无效 | View Transitions 期间元素不可点，`pointer-events: none` 不生效 | 按下时中断转场并把点击转投给真实元素 |
| 共享元素转场互相遮挡 | 列表每项都起了共享名 | 只给当前项起名 |
| 滚动驱动动画失效 | 祖先 `overflow: hidden` | 改用 `overflow: clip` 或调整结构 |
| 路由更新后点击偶发无响应 | 路由提交与重渲染竞争 | 路由更新同步提交，导航拆为独立组件 |
| 切主题后画布颜色不变 | 画布只在挂载时读颜色 | 从元素自身读语义色，主题变化时重画 |
| 亮底上的粒子发白 | 加法混合在亮底上溢出 | 亮底用普通叠放 |
| 打开某页卡数秒，耗时都在 `drawImage` | 画布滤镜逐笔生效，在 `drawImage` 时统一结算 | 先叠加后整体滤镜一次 |
| 静止页面掉帧、发热 | 每帧重画静态大图层 | 静态层与动态层分开 |
| `color-mix()` 不生效 | 百分比超过 100 | 修正参数 |
| 新 CSS 特性在 WebView 表现异常 | `text-wrap`、`color-mix` 等支持差异 | 在目标 WebView 上检查 |
| 无头浏览器里视频加载失败 | 缺少 H.264 解码 | 不是缺陷；用真浏览器确认 |
| 测试本地过、CI 失败 | 依赖日期或时区 | 不写死随日期变化的值 |
| `pkill -f` 杀掉了自己的 shell | 命令行里含相同字符串 | 用精确匹配找到 PID 再杀 |
| 设计工具插件里自动布局框高度被固定 | 对自动布局框调用了 `resize()` | 不对自动布局框 `resize()` |
| 平台注入的密钥不生效 | 绑定的域名与接口域名不一致 | 绑定接口域名，或改用环境变量 / 密钥文件 |
| 外部参考站打不开 | 云环境网络策略 | 改用本地资料 |
| 列表页满屏中性实心块 | 中性色承担了太多角色，焦点色又被完全禁用 | 焦点色分面与点缀两级；重复标记用线 / 点 |
| 页面「没设计感」 | 结构没想清，在表现层堆装饰 | 回到结构层 |
| 切主题时画面闪一下、几块先后换色 | 画布特效在换主题后才逐个重画 | 换主题只走一个入口，用固定时长的全屏转场盖住重绘：盖满时才换、等两帧再揭开；遮罩不吞点击，中途再点排队 |
| 逐帧截动画，帧对不上时间 | 截图本身耗时，浏览器虚拟时钟装上后默认仍在走 | 装虚拟时钟后先暂停，再按步推进时间截帧；动画里统一用 `performance.now()`，不用帧回调给的时间戳 |

### G · 展示用手机样机
原则：素材里只有一台手机（阴影、地面由合成脚本生成）；屏幕是纯绿幕；屏幕位置用蒙版拟合而不是直线求交；每步有量化自查，不过关就重出素材。
步骤：出素材（每个姿势 2 张，长边 ≥ 2752）→ 自查 → 抠图（机身蒙版 ∪ 绿幕、边缘吸附、去色边）→ 拟合屏幕四角并贴入截图 → 合成接触阴影与投影 → 按机身包围盒（不含阴影）入版。
自查：背景四角亮度 ≥ 240、方差 ≤ 3；绿幕接近 (0,255,0) 且只有一个连通域；四周留白 ≥ 8%；机身下缘外第一像素即纯白（无接触阴影）；屏幕四角完整、无遮挡；边缘锐利；无 logo。
提示词（通用部分）：

Long lens 85–100mm, minimal perspective distortion, sharp focus edge to edge, no motion blur, no depth-of-field blur, photorealistic, minimal, high resolution.
负面词：`shadow, contact shadow, ambient occlusion, floor, reflection, vignette, gradient background, halo, glow, multiple phones, hands, text, logo, screen glare, green light spill, fisheye, bokeh, motion blur`
常见问题：机身下缘脏边 → 素材含接触阴影，重出；某条屏幕边对不上 → 改用蒙版拟合，被遮挡区域不参与计算；优化器四角不动 → 手写绝对步长有限差分；屏幕边缘锯齿 → 透明度取绿度连续值；白底毛边 → 收紧阈值并去色边；拟合慢 → 缩到长边 ≤ 1000 拟合再放回。开源抠图模型不输出半透明投影，所以投影只能在合成阶段生成。
