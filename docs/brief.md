# 慢牛 Milo 产品 Brief

> 阶段 1 · 产品定义 · v1.2（已冻结） · 2026-10-03
> 上游输入：V1 走查结论（`GYMLOGrepo` v1.1.40 提炼）、用户在阶段 1 启动时的四项决定（见文末「决定记录」）
> 后续阶段的名词与数字只从本文取。

## 一句话定位

给刚过新手期的健身爱好者的 Android 训练 App：根据你的恢复、训练量和近期表现，告诉你今天练什么、每组加多少，帮你跨过进阶的门槛。

## 命名

- 中文名 / 英文名：**慢牛** / **Milo**（取自古希腊力士米洛；与同名饮料品牌的联想靠语境区分，必要时用变体 Mylo）
- Slogan：**慢慢变牛。**
- 功能说明句（用在商店简介和引导页，不当 slogan）：下一组，该加多少，它告诉你。
- Logo：方向待阶段 3 定稿。起点是几何化的牛角，或一条缓升的曲线；只用几何图形，不画人体，也不画写实的牛。
- 代号：仓库沿用 `gymlog`，不影响对外名称。
- 命名逻辑：「慢牛」在股市里指缓慢但持续上涨的行情；牛又是力量的象征。渐进超负荷就是肌肉的慢牛行情，一次只多一点，一直在涨。典故可作为作品集里的一句话故事：古希腊力士米洛每天扛起一头小牛，直到它长成公牛。
- 语气分工：名字和 slogan 俏皮，只出现在品牌位置（启动页、关于页、商店简介）；功能界面的文案保持中性、克制，避免和财经词汇混在一起。

**候选对比**（2026-10-03，参考主流应用的命名逻辑后重选）

| 候选 | 命名逻辑 | 结论 |
|---|---|---|
| ✅ 慢牛 | 角色加行话（超级猩猩一路）；股市「慢牛」双关加力量的牛 | 选定：双关自带故事，和「克制、笃定」不冲突 |
| 加码 | 命令式动词（Keep 一路）；加砝码 / 加大筹码 | 备选：英文名难取 |
| 余力 | 对应 RIR 的概念诗化 | 备选：偏教学，同类英文名已不少 |
| 增量 | 直述功能 | 淘汰：没有记忆点 |
| 进阶 / 处方 / 下一组 / GYMLOG | 直述功能或品类词 | 淘汰：同质化；GYMLOG 还和 GYMANIAC、iron-log 并存 |

排除项：Notch、Spotter、Microload 在应用商店已有同类产品。查重只做了搜索引擎粗查，作品集不上架，风险可接受。

## 平台

- Android APK（Capacitor 打包，GitHub Actions 构建），真机验证在用户自己的手机上。
- 主要尺寸：360 × 800 dp 起，覆盖 360–430 dp 宽；竖屏；单手拇指可达为布局前提。
- 仅本地存储，无账号、无后端。作品集展示用，不上架。

## 目标用户

主要人群：**刚过新手期、想进阶的健身爱好者，不分性别。** 训练 6–24 个月，线性加重开始卡住。

| 人群 | 典型场景 | 痛点 |
|---|---|---|
| 刚过新手期、线性增重停滞的爱好者 | 在健身房，手里拿着手机，组间休息 1–3 分钟；下次训练前想知道该加多少 | 不知道下一组该上多少重量；不知道什么时候该减载；网上的计划照搬下来不贴合自己；现有记录类 App 只是一本账 |
| 自己排计划、但没有训练量和恢复概念的爱好者 | 每周练 3–5 天，计划是自己拼的 | 不知道某个肌群是练多了还是漏了；不清楚今天该练哪块、该练几组；练了很久也说不清自己进步了多少 |

**性别说明**：功能和引擎不分性别；性别只影响肌群图的体型示意和展示用语，不改变处方逻辑。V1 女性视角走查里的教训（设置不能静默回退、围度要能看左右差、输入要有范围限制）作为设计约束保留，写入 `DESIGN.md` 和 `ia.md`。

## 产品目标

用户价值的指标，都要能在 MVP 可用性测试中验证（建议 5 名训练者，每人用真机走一遍闭环）。

| 类型 | 目标 | 衡量指标 |
|---|---|---|
| 用户价值 | U1 打开就知道今天练什么、首组用多重 | 从启动到看到「今日首个动作的建议重量」≤ 10 秒且 ≤ 3 次点击；5 人中 ≥ 4 人无提示完成；测试账号需已有至少 1 次训练记录（冷启动时没有历史，引擎不给建议重量） |
| 用户价值 | U2 组间记录又快又准 | 采用建议值时，记一组 ≤ 2 次点击；5 人中 ≥ 4 人无提示记完一个动作的全部组 |
| 用户价值 | U3 练完能看到自己进步了 | 完成结算后，5 人中 ≥ 4 人能正确说出「本次比上次变化了什么」（重量、次数或 e1RM） |
| 用户价值 | U4 看得懂建议为什么这样给 | 5 人中 ≥ 4 人能在处方详情里找到并说出一条依据（如「胸部恢复 82%」） |
| 业务目标 | B1 工作流完整走完 | 六个阶段的门禁全部通过；附录 F 的写死值检查在 `src/pages`、`src/components` 命中 0 |
| 业务目标 | B2 可演示、可安装 | 一条 5 分钟内可走通的 Demo 流程；APK 在真机安装并走通核心闭环 |
| 业务目标 | B3 自适应引擎可信 | 引擎单元测试 ≥ 40 项通过（由 V1 的 40 项自检迁移改写），覆盖恢复、容量、趋势、减载四类规则 |

## 核心体验闭环

看今日处方 → 记组（建议值预填）→ 组间休息 → 完成结算 → 进度回看 → 回灌下次处方

回看的数据（e1RM 趋势、近 7 天容量、恢复度）正是下一次处方的输入，所以这是一个闭环，而不是一条直线。

### 不做（非目标）

- 节拍器、呼吸训练、语音教练（V1 的 TempoMetronomeModal、RestBreathingModal、speechCoach）：偏离「告诉你下一组加多少」的主线。
- 战报海报分享（victoryPoster）、开屏动画、训练 HUD 与工具箱弹窗（TrainingHudModal、TacticalToolboxModal）：装饰性强，不服务闭环。
- 多主题切换（V1 有 6 套）：视觉方向在阶段 3 只定一套。**初版只做深色主题**（2026-10-03 用户决定）；浅色不在初版，以后要做时再回到阶段 4 补一套 Token。
- 大字模式：字号下限由阶段 4 的视觉规范保证（V1 的正文 10 px 是教训），不另做模式。
- 账号、云同步、社交、排行榜、付费：作品集展示，不涉及。
- 饮食、睡眠、体重管理：属于食律的范围，本产品不重复做。
- 面向新手的教学课程与动作入门引导：目标人群是已经会练的人。

## 竞品与差异

| 竞品 | 他们怎么做 | 我们的差异 |
|---|---|---|
| Strong / Hevy 类（记录型） | 记录又快又全，有历史和图表；重量靠用户自己决定 | 我们记完之后还会回答「下一次加多少」；记录是手段，处方才是产品 |
| Fitbod 类（生成型） | 自动生成训练内容，偏订阅制和黑盒 | 我们把依据摊开给用户看（恢复度、容量、趋势），给得出理由，也允许用户理解后改 |
| 通用健身 App（带课程与视频） | 内容为主，课程和打卡 | 我们不做课程；面向已会练、想自己进阶的人 |

## 统一口径表

| 类别 | 统一写法 | 说明 |
|---|---|---|
| 术语 | 处方 | 引擎针对某一次训练给出的动作、组数、次数区间和建议重量。不叫「推荐」「计划」「AI 建议」 |
| 术语 | 计划 | 用户预先排好的训练模板。与「处方」不同：计划是固定的，处方是每次现算的 |
| 术语 | 训练 | 从开始到完成的一次完整记录；列表里叫「训练记录」 |
| 术语 | 动作 | 一个训练项目，如「杠铃卧推」。不叫「项目」「练法」 |
| 术语 | 组 | 一组连续重复。类型固定为：热身组、工作组、递减组 |
| 术语 | 建议重量 | 处方给出的某一组重量；用户实际记录的叫「实际重量」 |
| 术语 | e1RM | 预估单次最大重量，取 Epley 与 Brzycki 两个公式的平均值（沿用 V1 的 `estimate1RM`），界面写「预估 1RM」 |
| 术语 | RPE | 自觉用力程度，1–10；界面写「RPE」并配一行说明 |
| 术语 | 恢复度 | 某肌头距上次训练的恢复百分比。基础窗口：大、中、小肌群分别为 72 / 48 / 24 小时（沿用 V1 引擎的 `TIER_HOURS`），实际窗口再乘以训练量、力竭度、经验和个人系数 |
| 术语 | 恢复时相 | 四档：修复期（恢复度 < 50%）、恢复中（50%–100%）、黄金窗（超过窗口、不到 2 倍窗口）、已回落（超过 2 倍窗口） |
| 术语 | 力竭度 | 训练结束时用户自评的 1–10 分，默认 8，用于恢复窗口计算；与「RPE」（单组自评）不同 |
| 术语 | 总负荷 | 一次训练（或一段时间）内，所有已完成工作组的「重量 × 总次数」之和，单位 kg；与「近 7 天容量」（组数）是两个量，界面和文档不混用「容量」指总负荷 |
| 术语 | 近 7 天容量 | 滚动 7 天内某肌头的有效组数（已完成的工作组；主练 1 组记 1，协同记 0.5）；对照 MEV / MAV / MRV 三档，界面写「最低有效量 / 适宜量 / 最大可恢复量」。不用「本周」，因为不是自然周 |
| 术语 | 减载 | 一周内主动降低训练量或重量以促进恢复；由引擎判断并提示 |
| 术语 | PR | 个人纪录：某动作的预估 1RM 创该动作的历史新高（只算工作组）。全产品只有这一个口径 |
| 数值 | 训练经验 | 三档：新手 / 进阶 / 高阶（对应引擎的 novice / intermediate / advanced）；目标用户默认进阶 |
| 数值 | RPE 步进 | 0.5，范围 1–10 |
| 数值 | 重量取整 | 按器械步进取整，默认 2.5 kg（自重、弹力带 0.5 kg），沿用引擎 `LOAD_STEP` |
| 单位 | 重量 | kg（lb 切换为 P1）；界面「80 kg」数字与单位之间留一个空格 |
| 单位 | 时间 | 组间休息写「1:30」；训练时长写「52 分钟」 |
| 单位 | 日期 | 「10 月 3 日」；跨年写「2026 年 10 月 3 日」 |
| 权益 | 无 | 无账号、无会员、无付费；所有功能对所有人开放 |

## 品牌关键词

- 笃定（给出明确数字，而不是「看感觉」）
- 透明（每个建议都能展开看到依据）
- 扎实（器械与数据的质感）
- 有张力（力量感，对比强，节奏有起伏）
- 器械感（金属、刻度、配重片、插销这类物理世界的语汇，转译成界面）

## 视觉与交互定位

- **与食律的区别**：食律是克制平淡的工具型界面；慢牛是作品集里的视觉主秀，鼓励有辨识度的视效和动效，追求审美，而不是中性模板。
- **三条约束**：
  1. 视效必须服务信息，不能为了炫技牺牲信息；
  2. 不能拖慢 P0 任务，U1、U2 的指标仍是硬约束；
  3. 每个标志性视效都要有静态可读的降级（系统开启「减少动画」时）。
- **已确认保留的标志性交互**：容量与恢复页的「放大镜胶囊」——人体示意图 + 引线连接的肌头胶囊，按住胶囊轨道上下滑动，手指处的胶囊像 Dock 一样放大，显示详情。它来自 V1，是用户最满意的设计；在新项目里按功能规格（`ia.md` §1.10）重做，并修掉 V1 里静止时看不到肌肉名称的问题。
- **已确认的第二个签名交互（P1）**：导航胶囊环（`ia.md` §1.12）。与放大镜胶囊是同一种造型语言。
- **视觉方向（阶段 3 选定）**：「配重片」——近黑底、单一荧光黄绿强调色、全圆角胶囊，吸收「刻度」方向的刻度条与等宽读数；初版只做深色。理由与规矩见 `references.md` §9。
- **候选视效（阶段 3 提案，通过后以 P1 加入）**：启动、PR 达成、训练结算这几个「品牌时刻」；肌肉随恢复度渐变的呼吸感；休息计时的物理隐喻（配重片、插销）。开屏动画仍在非目标里，除非阶段 3 的提案证明它值得。
- **语气分工**：名字和 slogan 俏皮，只出现在品牌位置；功能界面的文案保持中性、克制。
