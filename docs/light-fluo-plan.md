# 浅色「荧光不够亮 / 页面发脏」治理方案

> 2026-10-10 拟定，**待用户拍板后动手**。起因：用户在看完浅色截图后指出「浅色背景太白，荧光绿视觉上不是页面最亮的元素；特效叠了一层灰底看起来发黑；曲线端点、PR 角标、进度条等点缀有同一个问题」。
> 铁律：**深色主题一像素不变**（见 §6）。

## 结论先行
问题是同一个根因的三种表现，不是三个独立 bug：

1. **荧光的明度本来就比页面低**（§1）：浅色里荧光再亮也亮不过纸白卡，「最亮的元素」这个深色里的视觉层级在浅色里塌了。
2. **点缀被换成了深绿**：为了在纸白上看得清，浅色把荧光字 / 线 / 点统一换成 `accent/ink`（`lime-750`，明度 0.115，近乎黑），所以曲线端点、PR 角标、进度条看上去是「一个深色点」，不是「一点荧光」。
3. **特效下面垫了灰**：流体背景的骨灰光斑、颗粒贴图（中灰）、灰阶色带 multiply、灰色面积图，在纸白上叠出一层灰膜，荧光透过它就发暗发黑。

治法也是一条：**浅色里「亮」不靠明度，靠「荧光芯 + 深绿细边 + 外光晕」的固定配方，加上把荧光放在比它略暗略灰的底上**。分 4 期，每期都先上方案台让用户选，再批量替换。

## 1. 根因数据（`tokens.json` 实测）

| 颜色 | 相对明度 | 备注 |
|---|---|---|
| paper-50（卡片 `bg/raised`） | 0.965 | 浅色里最亮 |
| paper-0（页面 `bg/base`） | 0.871 | |
| lime-500（深色荧光面） | 0.858 | 比页面底还低，对比度 1.01 |
| lime-550（浅色荧光面 `accent/default`） | 0.762 | 对卡片 1.25:1 |
| lime-750（浅色荧光字线 `accent/ink`） | 0.115 | 近黑，「深色点」的来源 |
| 深色页面底 gray-0 | ≈ 0.005 | 荧光 0.858 是全屏最亮 |

→ 深色里荧光是最亮的东西（对比 > 12:1），浅色里它**既不比卡亮、也不比底亮**，只剩色相差。所以：
- 荧光面（按钮、该加重条）：能靠色相撑住，但没有「发光」感；
- 荧光点缀（端点、角标、进度）：被迫用深绿，读成「深色」；
- 一旦下面再垫一层灰（特效），荧光被拉进灰里，读成「脏」。

## 2. 原则（新增，写进 DESIGN §1.5）
1. **浅色里「亮」= 饱和度 + 周边对比 + 自发光**，不是明度。荧光永远要有「容器」：深绿细边（对比）+ 外光晕（自发光）。
2. **点缀 = 荧光芯 + 深绿细边**，不是纯深绿实心。字仍用 `accent/ink`（要可读），但**点、标、条的「面」用荧光**。
3. **荧光放在比它略暗略灰的底上，不放在最亮的白上**：荧光面周围留一圈 `bg/raised-2` 级的暖灰衬底，荧光才「跳」出来。
4. **特效下面不垫灰**：浅色里光斑、颗粒、面积图一律用荧光 / 纸白的色，不用骨灰、中灰。
5. 荧光面积仍是每屏一处（沿用原规则）；点缀可多处，但用同一配方。

## 3. 分期方案

### 第 1 期：底色梯度（先实验，决定后面的力度）
**问题**：页面底 / 卡 / 荧光三者明度几乎一样。**做法**：只改浅色的 `bg/*` 映射（深色不动），在方案台新增「浅色底色 · B」组，四个方案各配三屏真实页面（首页 / 容量 / 增量），实时渲染：

| 方案 | 页面底 | 卡片 | 荧光面 | 想验证什么 |
|---|---|---|---|---|
| B0 现在 | paper-0 `#F2F0EA` | paper-50 | lime-550 | 对照 |
| B1 底降一档 | **paper-100** `#E8E5DC` | paper-50 | lime-500 `#D4FF3A`（浅色也用深色那个更亮的荧光） | 卡浮起来、荧光比底亮一截 |
| B2 底降两档 | **paper-200** `#DCD8CD` | paper-50 | lime-500 | 对比最足，但整体偏暗，和「深色太多」有冲突 |
| B3 底不动、荧光加框 | paper-0 | paper-50 | lime-500 + 深绿下沿厚边（像按钮的凸边）+ 外光晕 | 不动底，靠容器撑荧光 |

推荐先看 **B1 / B3**；B2 作为极限对照留着。评判标准：荧光面与相邻底的对比 ≥ 1.4:1，且整页没有「变灰变脏」。
**涉及**：`design/tokens/tokens.json` 的 `bg/base` `bg/raised-2` `accent/default` 的 `light` 值（+ `build_tokens`）；荧光面上的文字 `text/on-accent` 对比度跟着重测。

### 第 2 期：点缀统一配方（同源问题一块改）
**新增语义色**（浅色值新、深色值 = 现有原色，深色不变）：
- `accent/spot`：荧光点缀的「芯」（深色 lime-500，浅色 lime-500）；
- `accent/spot-edge`：芯的深绿边（深色 = 透明，浅色 lime-750 的 85%）；
- 光晕沿用 `accent/glow`。

**配方**（浅色专用选择器 `:root[data-theme='light'] .x`，深色选择器不动）：
`fill: accent/spot` + `stroke: accent/spot-edge 1px` + `drop-shadow(0 0 4px accent/glow)`。

**逐项清单**（grep `accent-ink` 的点缀类用法，约 17 个文件）：

| 点缀 | 位置 | 现在（浅色） | 改成 |
|---|---|---|---|
| 曲线端点 / PR 点 | `charts.module.css:50,53`（`.spark .last .pr`） | 深绿实心 + 淡光 | 荧光芯 + 深绿边 + 光晕 |
| 曲线日历「今天」点 | `charts.module.css:23`、`dataviz.module.css:10` | 深绿环 | 荧光芯 + 深绿环 |
| PR 角标 / 星 | `gains.module.css:62-64` | 深绿字 + 深绿细框 | 荧光底（`accent/spot`）+ 深绿字，去外框 |
| 上涨箭头 / 数字 | `gains.module.css:64` | 深绿字 | 字保留深绿（要可读），数字旁加荧光小方块点缀 |
| 进度条 / 小级进度 | `growth.module.css:21,27`（`.pips .pipOn`、箭头进度） | 深绿 2px 线 | 荧光填充（`accent/spot`）+ 深绿边 + 光晕；轨道 `data/track` |
| 标签 `tag_accent` | `ui.module.css:31` | 深绿字 + 深绿细框 | 荧光底 + 深绿字 |
| 导航今日进度环 | Nav | 深绿线 | 荧光线 + 外侧深绿细边 |
| 方案台里的同类（J1–J3、T1–T3） | `OptionsBoard` | 同上 | 随全局 |
| 面积图 / 曲线 | `data/spark-area`（lime-300 45%，浅色里发灰米）、`data/spark-line` | 灰米面 | 面积图改荧光 20% 渐变到透明，线 `accent/spot-edge` |

> 不改：荧光**字**（标题强调、数字上的荧光字）仍用 `accent/ink`，要保证可读。

### 第 3 期：特效去灰
逐个特效，定位「灰」从哪来、浅色里怎么换（都只动浅色分支）：

| 特效 | 灰的来源 | 浅色改法 |
|---|---|---|
| 流体背景 `FluidBackdrop`（`atmosphere.tsx` `BLOBS_LIGHT`） | `bone-500` 骨灰光斑 + `lighter` 叠加；荧光斑透明度高、叠在暖灰上发黄绿 | 去掉骨灰斑；荧光斑改小、降透明度、按页面分级（Tab 根页最淡）；或按第 1 期结果换成「纸白 + 一点荧光」 |
| 颗粒 `--grain`（`atmosphere.tsx`，中灰贴图 + overlay） | 中灰颗粒在纸白上 overlay 会发脏 | 浅色降到 ≈ 40% 透明，主角卡用带荧光色的颗粒 |
| 主角卡 `GrainGlow`（H4 脉搏光团） | 光团叠在灰底卡上 | 浅色里光团用 `fx/glow-hot` 荧光、垫一层纸白，不叠灰 |
| 流体粒子 `ParticleField` | 浅色改 `source-over` 后粒子颜色偏深（spark-0 = lime-750） | 浅色用荧光芯 + 极淡深绿边，粒子透明度分层 |
| 钢板（记录页） | 浅色拉丝铝板 `paper-200 → paper-100` 灰米 | 更亮的银白（`paper-50 → paper-100`），孔里荧光保持，孔壁阴影减淡 |
| 容量人体 | 已治（L2d 磨砂）；未练肌肉 `tier-none` 灰斜纹 | 斜纹压到 12% 透明度，肌头底用 `paper-50` |
| 灰斜纹（未练胶囊、「该减重」条、`data/tier-*`） | `ink-500` 灰斜纹 | 浅色里斜纹压淡、颜色换暖纸色 |
| 奖励 / 增长卡 | 荧光闪 + 骨白高光叠在白卡上 | 复查一遍，按配方统一 |

### 第 4 期：大块纯黑的选中态
用户要的是「整体深色太多」。涉及：增量页汇总条（黑块 + 黑刻度）、选中的 `Chip` / `Segmented`（正面 / 男 / 全部）、导航选中项。**这些是全 App 共用组件**，所以单独成期，三个方案先上方案台：

| 方案 | 选中态 | 注意 |
|---|---|---|
| S1 荧光芯 | 荧光底 + 深绿墨字 | 一屏会出现多个荧光面（Segmented ×2 + Chip + 主按钮），违反「荧光面积一屏一处」；需要放宽或只给导航用 |
| S2 墨线 + 荧光条（推荐） | 纸白卡 + 深绿墨字 + 底下一道荧光短条 + 轻阴影 | 不违反荧光面规则；选中靠「荧光条」读出 |
| S3 保留黑但缩小 | 保持墨黑，缩小面积（Segmented 更小的 pill） | 改动最小，但「深色太多」没真正解决 |

增量汇总条：黑块 + 黑刻度 → `bg/raised-2` 底 + 荧光（涨）/ 灰（平）/ 浅红绿（退）三段 + 墨线刻度。

## 5. 验收标准
- **荧光点缀可见度**：门禁新增「荧光芯」检查——点缀元素的填充 = `accent/spot`、有 `accent/spot-edge` 边；荧光面对相邻底对比 ≥ 1.4:1（第 1 期选定后写进 `light_checks`）。
- **文字对比度**：浅色 `check:contrast` 全绿（荧光面上的字、深绿字、选中态字）。
- **目测**：首页 / 容量 / 增量 / 记录 / 我的 五页的浅色截图，用户确认「荧光是视觉重点、不脏」。
- 门禁：`npm run check` + `shoot_6a.py` 全套；light 类用新增检查。

## 6. 保证深色不变的做法
1. **所有改动只写在 `light` 值或浅色专用选择器里**：`tokens.json` 只改 `light` 字段、新增 token 的深色值 = 现有原色；CSS 的新规则一律写成 `:root[data-theme='light'] …` 或 `[data-theme='light'] …`（方案台 / Playground 单格强制深色时也不受影响，上一轮已验证这种写法）；深色走的代码路径一行不动。
2. **特效代码按 `theme` 分支**：`atmosphere.tsx` 已有 `theme === 'light' ? BLOBS_LIGHT : BLOBS`，新增调整只改浅色那份。
3. **深色逐像素回归**：上一轮的回归脚本在旧 scratchpad、已丢，**第 1 步先重写**，并在动手前**先对当前提交截基线**：
   - 路由：`/today` `/body` `/gains` `/log` `/me` `/me/level` `/shop` `/pro` `/onboarding?scene=1..8`，以及 `/playground`（逐格按 key）、`/preview`（逐格）；
   - 冻结动画、固定 `Math.random` 种子、Playwright 假时钟，隐藏画布后比；
   - 基线与候选逐像素比，只允许休息倒计时、钢板固定光源这类已知噪声。
4. 每期结束都重跑一次回归，不等到最后。

## 7. 顺序与节奏
0. 重写深色回归脚本 + 截基线（半小时级）
1. 第 1 期：方案台「底色 B」→ **用户选** → 改 token
2. 第 2 期：点缀配方 + 批量替换（同源，一次改）
3. 第 3 期：特效去灰
4. 第 4 期：选中态方案台 → **用户选** → 批量替换
5. 每期：`check` + 门禁 + 深色回归 + 文档同步；推分支后给用户看截图

用户要拍板的点（均在方案台）：**B 组底色**、**S 组选中态**；其余按 §2 的原则直接做。

## 8. 风险与取舍
- B2（底降两档）会让页面更暗，和「整体深色太多」冲突，所以只当极限对照，不作推荐。
- S1（荧光选中态）违反荧光面每屏一处的规则，需要先在 DESIGN 里放宽才能做。
- 荧光芯 + 深绿边在小尺寸（端点 < 6px）上边会糊成一个点：端点做大半档或用外光晕代替边，方案台里用真实页面验证。
- Stitch 密钥这个容器里没有，所以不走 Stitch 视觉参考这一步，直接在方案台用真实组件对比（用户 2026-10-10 说先不管 Stitch）。
