## 1. 使用前提（继承自 brief「视觉与交互定位」）

1. 视效服务信息，不能为了炫技牺牲信息。
2. 不拖慢 P0：U1（看到今日处方）、U2（≤ 2 次点击记完一组）仍是硬指标，P03 记组主路径上的任何动效都不得阻塞输入。
3. 每个视效都有静态降级：系统开启「减少动画」时，只保留状态变化，不做位移、缩放、旋转、连续动画。

补充规则（本文新增，待评审）：

- **预算**：单次转场 ≤ 350 ms；列表进入的总时长 ≤ 300 ms（超过前 4 项的条目同时出现）；按下反馈 ≤ 100 ms 起效。
- **只动合成层属性**（transform、opacity）。避免对大面积元素做持续的模糊或渐变重绘；持续动画只在元素可见时运行，页面离开即停。
- **P03 记组页禁用持续动画**（旋转光边、呼吸光晕等），只允许一次性的短反馈。
- 动效参数统一进阶段 4 的动效 Token（时长、曲线、弹簧刚度），页面里不写散落的数字（附录 F 的 grep 同样检查）。
- 低端 Android 机型上的表现必须在阶段 6 真机验证；掉帧则降级，而不是降低其他页面的标准。

## 9. 选定方向与理由（2026-10-03 用户确认）

**选定：B · 配重片为主，吸收 A 的刻度。** A、C 淘汰（留档不删，见 §8）。 具体是：B 的底色、单一荧光强调、全圆角胶囊、噪点、「每屏一处发光」；从 A 借两样——放大后的胶囊与详情面板里的**刻度条**（最低 / 适宜 / 上限三条地标）、读数处用等宽数字防跳动。C 不选。

理由：

1. **对上品牌关键词**：「有张力」需要强对比和明确的主角，B 是三个里唯一有「主角」的（荧光 + 发光只给一个元素）；「器械感」由配重片的造型和颗粒表面承担，不靠拟物。「透明 / 笃定」由借来的 A 刻度补上——依据（三条地标）始终画在数字旁边。
2. **对上「视觉主秀」的定位**：brief 要求慢牛比食律更有辨识度。A 太像工具，放进作品集和食律站在一起区分度不够；B 的黄绿近黑在缩略图尺寸下也认得出。
3. **对上用户给的参考**：8 张里有 4 张（ref1、ref4、ref5、iconmotionref1）直接落在 B，导航形式（ref2）在 B 里最自然——选中的小胶囊本身就是荧光实心块，休息描边绕着它走。
4. **C 的问题**：多层渐变、内外阴影和拉丝纹理在每个胶囊上叠加，放大镜要跟手连续重绘（ia §1.10「不出现掉帧」），中低端 Android 风险最高；拟物也最容易过时。
5. **三条约束**：B 的发光只在两处静态位置、进度环的「轨迹」是静态渐变，都不是持续动画；P03 记组页不受影响（见 §9.5）。

**一句话差异（过关标准 1）**：记录型竞品是系统蓝的清单和柱图，Fitbod 是一张只有恢复度的热力图；慢牛是近黑底上只亮一处荧光的「器械面板」——人体图连着带名字和刻度的胶囊，每个数字旁边都摆着依据。

### 9.1 选 B 之后要守的规矩（进阶段 4 的 `DESIGN.md`）

- 荧光色只给三类东西：**当前主角**（放大的胶囊、今日处方卡）、**导航选中项**、**进度**（导航环、P01 进度）。正文、图标、分割线一律不用。
- 发光（光晕）每屏最多一处，与 §1 的「06 Conic Glow 每页一处」合并计算；导航选中项是实心填充、不发光，不占这个预算。
- 「超量」不能用荧光（会被读成「好」），用白底黑斜纹；警告类语义另需一个颜色时，阶段 4 再定，不在方向稿里加第二种强调色。
- 噪点只放在大面积的主角卡和底部面板上，不放在列表项和胶囊上。

### 9.2 「减少动画」降级（过关标准：每个入选视效都有）

### 12.1 结论：推荐不变，B 的理由更充分

- **D 自己推出来的方向，两轮都是琥珀橙的仪表风**，和 A 几乎一样；C 的第 2 轮也滑向了「琥珀 / 红 + 工控标签」。说明「深色 + 琥珀 + 刻度」是模型眼里「器械感」的默认答案，也就是最不稀奇的那个。A 在作品集里辨识度弱的判断，又多了一条证据。

### 12.3 要避开的（反例）

1. **编造的英文技术标签**：「CALIB-24」「SYS.LOCKED」「RX // TARGET EXERTION」「SPEC-2024-X」「MILO // REC」，以及中文版的「处方负荷校准」「杠铃盘位负荷」。违反 brief「功能界面文案中性、克制」，也违反「视效服务信息」。写进 `DESIGN.md` 的禁止项。
2. **Stitch 会自己补数字**：例如中下胸「需 36h」（引擎算出来约 70 小时）、「继续训练（第 3 组）」（卧推一组还没做）、「RPE 8.5」（提示词里没有）。**Stitch 图里的数字一律不能当口径**，口径只看 brief / ia。
3. **荧光泛滥**：run2 B-P01 同时有荧光按钮、荧光当前行、荧光导航，一屏三处荧光，焦点就没了。这是 §9.1「荧光只给三类东西」的反例。变体加了规则之后才回到白色按钮。
4. **红色当主按钮**：run2 C-P01 的「继续训练」是整条信号红，和 C 自己定下的「红只做指示」矛盾。
5. **「机甲」化的人体**：多张图把人体画成装甲块或机器人，偏离「只用几何、不画人体细节」的气质，也会让肌头位置变得难读。
6. 变体 B-P06-1 的图例把「超量」画成了橙色。即使加了规则，「超量」用什么颜色 Stitch 仍然守不住，阶段 4 必须在 Token 里定死。
